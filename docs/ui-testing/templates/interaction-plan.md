# UI 交互计划模板

> **用法**：每个 UI 测试任务先填本计划，再执行。三模式：**observe（读）/ drive（写）/ multi-step（编排）**。
> **原则**：需求驱动（只做需求要的）；驱动必带安全边界与验证；多步每步独立可验证。

---

## 任务
<目标，例如"从 AcmeHR 招聘系统抽取候选人列表并自动标记已面试者">

## 模式: <observe | drive | multi-step>

### observe（抽取 / 校验，不改变 UI 状态）
- 抽取字段：<字段列表>
- 对照契约：`<acceptance/ui-testing/xxx.yaml>`
- 输出：结构化数据 + provenance 报告

### drive（仅当需改变 UI 状态）
- 动作序列：<点击 / 输入 / 导航，逐步列出>
- **安全边界检查**（必填）：是否触及人审边界（登录 / 支付 / 删除 / 对外发消息）？
  - 是 → **停下问人**，不自动执行
  - 否 → 继续，但仅自动化可逆且可观测动作
- 验证方式：动作后**重序列化 + 状态 diff 断言**（非再截一张图让模型猜）
- 改前备份：若改变状态 / 配置，先备份

### multi-step（编排）
```yaml
steps:
  - id: 1
    mode: observe
    do: <抽取 A 系统数据>
    assert: <对照契约断言>
  - id: 2
    mode: drive
    do: <写入 B 系统>
    assert: <重序列化 + diff 断言>
  - id: 3
    mode: observe
    do: <回读 B 系统确认>
    assert: <最终契约断言>
```

## 预算与检查点
- 时间上限：<如 120s>
- 动作次数上限：<如 50 次>
- 到限前：存盘 + 交人，不烧光额度
- 升级机制：模糊 / 状态变更步骤 → 升级更强模型或人工
- fail-loud：断言 N 次内不满足 → 显式失败，不静默
